# AI Agent 全职冲刺计划 · 滚动版

> 前提：iOS/Flutter 10 年，强客户端/系统经验，弱生产级 Python 后端。
> 时间：全职，每天 8 小时，每周 5–6 天，约 240–280 小时。
> 目标：Agent 应用开发岗（BOSS 300 条 JD：应用开发 73.7%、Python 71.3%）。
> 规划方式：**只排当天，不排整周。** 周级只保留里程碑和验收标准，日任务每天按实际进度重新生成。
> 与 [12 周路线](AI-Agent自学路线-12周.md) 的关系：内容同源，按 2.5 倍时间密度压缩。

## 0. 学习形式：项目驱动，不跟课程

**载体就是自研 harness 项目，模型用 DeepSeek API。** 不把官方 DSH 当学习环境（本机 Node/macOS 版本不够），但可以读它的文档和架构作为参照。

每个模块走四步：

1. **定验收**：先写清「这个里程碑结束时能演示什么、有什么数字」。
2. **先写**：不看教程，按已有工程经验直接实现；卡住再查。
3. **定向补**：只查官方文档和源码，不系统刷视频课。
4. **对照**：写完后读一个开源实现的对应模块（Aider / OpenHands / DSH），记录差异与取舍。

### Python 零基础的处理

不会 Python 不影响路线，但「完全自己写」会卡在语法而不是概念上。按三段式推进：

| 阶段 | 谁写 | 你做什么 | 适用 |
|---|---|---|---|
| 示范 | 我写完整代码 + 逐行注释 | 跑通、复述逻辑、改 3 处 | M1 前半 |
| 模仿 | 我给函数签名 + TODO | 填实现，卡住给提示 | M1 后半–M2 |
| 独立 | 你写 | 我 review，只指问题不给实现 | M3 之后 |

规则：

- **核心模块最终必须你自己写一遍**：loop、tool call 解析、上下文裁剪、权限。可以照着参考写，但要能解释每一行。
- **不单独花两周学语法**。每天留 1 小时，只学当天代码里出现的语法，记进笔记。
- **用 Swift 类比**：`dict`≈Dictionary、`list`≈Array、`async/await`≈Swift Concurrency、`pydantic`≈Codable、`FastAPI`≈Vapor、`pytest`≈XCTest。
- **验收标准从「能写」改成「能解释 + 能改 + 能独立写同类」**。

**明确不做**：

- 不系统看视频课，不从第一页读 LangChain 文档。
- 不学 Docker / K8s / 本地模型：旧机没有，且应用开发岗 Docker 提及率仅 14.7%，不是硬门槛。
- 不并行学多个框架：LangGraph 为主，LangChain 只覆盖概念。
- 不追求代码完美：面试看能否讲清决策，不看行数。

## 1. 滚动规划机制

### 为什么不用固定日计划

按天排死有两个问题：某天卡住，后面全乱；为了「赶上计划」跳过验收，学得虚。滚动规划只承诺**下一个工作日**，每天根据真实进度重排。

### 规则

1. **规划窗口 = 1 天**。只写今天的任务，不写明天、不写本周。
2. **周里程碑是锚点**。里程碑的目标、验收、预算天数不随日计划变；变的是「哪几天做什么」。
3. **每日三次动作**：
   - 早上 10 分钟：看昨日记录，定今天 3 个任务（1 个主任务 + 2 个辅助），写进进度文件。
   - 晚上 10 分钟：记录实际完成、用时、卡点、明日候选。
   - 次日早上：根据记录重排，不机械顺延。
4. **未完成不自动顺延**。昨天没做完的任务，今天重新判断优先级：仍然关键就排第一，不关键就降级或删掉。
5. **模块预算防漂移**。每个里程碑有预算天数，超出 30% 就砍范围或换方案，不无限延长。
6. **周五验收，不按天卡**。周内某天落后不算失败，周五验收不达标才调整下周。
7. **任务粒度 1–2 小时**，必须可验证（能跑、能看、有数字），不写「学习 XX」这种不可验收的任务。

### 每日节奏（8 小时）

| 时段 | 内容 | 时长 |
|---|---|---|
| 上午 | 主任务：写新功能 | 3 h |
| 下午前半 | 调试 + 写测试 | 2.5 h |
| 下午后半 | 定向补知识（文档/源码） | 1.5 h |
| 收尾 | 写面试素材 + 记录进度 | 1 h |

### 效率规则

- 每个子任务 2 小时时间盒；卡住超过 30 分钟就换路径或查资料，不死磕。
- 先跑通再优化，MVP 优先。
- 面试素材边做边写，不等到最后。

## 2. 六个里程碑（只定验收，不定每天内容）

| # | 里程碑 | 验收标准（硬指标） | 预算 |
|---|---|---|---|
| M1 | Python 工程化 + DeepSeek 接入 | 能解释并修改示例；独立写一个同类接口；流式对话可跑 | 7 天 |
| M2 | 手写 loop + 工具 + 权限 + 事件日志 | 20 步任务完成；kill 后恢复；越界写入被拒 | 6 天 |
| M3 | 上下文工程 + RAG | 长对话不爆窗口；30 条问答有召回率与引用准确率 | 5 天 |
| M4 | LangGraph + 评测 | 中断后恢复；能画状态图；通过率与失败分类 | 5 天 |
| M5 | MCP + 可靠性 | 外部客户端接入 MCP；3 类故障后可恢复 | 4 天 |
| M6 | 毕业项目 + 面试材料 | 真实仓库端到端任务；README；3 个故障故事 | 5 天 |
| 缓冲 | — | — | 5 天 |

合计 37 个工作日，约 7.5 周（含 1 周缓冲）。里程碑顺序固定，日期不固定。

**工程化补充项**：`pip install -e .`（把项目装成可编辑包，替代脚本里的 `sys.path.insert`）安排在 **M6 收尾**时做。在它之前，所有脚本统一用 `python -m scripts.xxx` 从项目根运行。理由：editable install 会引入构建后端与 setuptools 版本排查，属于工程细节，不应打断 Agent 主线。

**依赖关系**：M2 必须在 M4 之前（先手写再上框架）；M3 的 RAG 评测集可复用到 M4；M5 的故障注入依赖 M2 的事件日志。
